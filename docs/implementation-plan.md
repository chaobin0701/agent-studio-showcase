# 实施方案 · 2026-10-16

用户已选择 Zola + Solid Free，并授权实现扫地机器人案例及配置本地 Agent。

## 视觉与内容

- 视觉主张：沿用 Solid 的白底、蓝色、薄荷色强调、宽松排版与产品插画；聊天沿用 Zola 的安静侧栏、中央对话和圆角输入框。
- 内容：品牌与入口 → 精选 Demo → 项目介绍 → 开放工具；删除模板的虚构客户、评价和定价。
- 交互：首屏渐入、滚动区块进入、Demo 行悬停；尊重减少动态效果偏好。聊天支持移动导航、历史会话、流式回答、错误与停止接收。

## 必须完成并验证

1. 独立同级 Next.js/React/TypeScript 项目，使用 Solid 和 Zola 实际源代码，保留来源、固定提交与许可。
2. 首页、项目目录/详情、Demo 目录/详情、多个聊天入口；独立品牌，Agent Studio 仅作为展示项目与后端适配器。
3. 扫地机器人知识问答、模拟用户、使用记录、天气模拟、个性化报告。数据与页面、HTTP、MCP 共用领域服务，身份与月份稳定可复现。
4. 通过 Agent Studio 公开平台 API 连接用户已运行的 Agent 5；本项目不复制模型凭证或执行内核。创建服务端接入密钥并仅存本地环境文件。
5. 外部工具以 HTTP/MCP 接入；更新业务 Prompt 和工具绑定；不在 Agent Studio 写入扫地机器人业务代码。配置变更保存前后记录，遵守既有测试、发布与网络策略。
6. 会话由 Agent Studio 保存；本站只保存匿名访客、Demo/模拟身份与会话路由。服务端校验归属，客户端不能指定平台 userId。刷新恢复、幂等、断流状态可见。
7. 数据明确标注模拟；沿用参考案例的 CSV 数据并保留许可，不将固定天气称为实时天气。报告模式用业务指导/Skill 表达，不复制 Python 动态提示词内核。
8. 类型检查、生产构建、领域/API/MCP/会话隔离测试，真实 Agent 的知识问答、工具天气与报告链路，桌面/移动浏览器验证；启动项目提供本地地址。

## 数据和安全边界

- `.env.local`、`.data/`、依赖、日志、构建与浏览器输出均忽略；公开仓库不包含任何运行密钥。
- 固定示例用户为公开模拟数据，不是真实登录账户。浏览器身份通过 HttpOnly 签名 Cookie 生成；用户切换模拟资料不改变他人的会话归属。
- 工具鉴权只在服务端；Origin 精确检查；本地工具网络仅按 Agent Studio 已有部署配置显式登记回环主机。
- 停止接收只关闭浏览器流，公开 API 不支持取消 Agent 执行；界面与文档如实说明，并提供运行状态恢复。

## 2026-10-16 入口简化

- 视觉：一个机器人 Demo 介绍块，下设三种特色功能，使用统一聊天 CTA。
- 内容：知识问答、报告、天气属于同一个助手；推荐问题一次展示九条，桌面 3×3，手机自适应。
- 交互：推荐分类筛选、换一组刷新九条、选中填入输入框；不切换 Agent、不新建会话。
- 兼容：旧入口重定向，旧记录统一列出但保留原始平台 userId，避免历史失去归属。
